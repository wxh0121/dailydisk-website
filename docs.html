DAILYDISK · 用户文档

安装、设置与日常使用

这份文档覆盖从构建安装到读懂报告的完整流程。更底层的架构、数据库与记账细节，见仓库中的 Docs 目录。

概述

DailyDisk 是一款以图形界面为主、从源码构建的 macOS 磁盘增长监视器。它把当前内置 APFS 磁盘的清单与上一次的状态比较，把文件增长归到具体路径，记录带符号的对账修正；当 APFS 的物理差异无法安全归属到某个路径时，就单独记录。

它监视的范围包括：

  • 内置 APFS 容器，以及其中 System、Data、VM、Preboot、Recovery、Update 各角色的卷
  • /System/Volumes/Data，作为启动盘上唯一的完整清点根
  • 来自 FSEvents 持久日志的历史文件变化
  • 新增、删除、移动、硬链接和尺寸变化的文件
  • 至少每七个滚动日一次的完整对账
  • APFS 快照成员关系和容器容量
  • 已删除但仍被进程打开的文件
  • DailyDisk 自身的数据库、报告和日志开销

密封的系统卷和其他不做清点的角色，仍以卷级指标显示。外置、可移除、网络和磁盘映像存储默认不纳入。

系统要求

项目要求
系统macOS 15 或更高，内置 APFS 启动盘
构建工具Apple 命令行工具（或完整 Xcode），提供 Swift 6+ 与 macOS 15+ SDK。全新的 Mac 通常没有预装。
网络首次克隆和解析 SwiftPM 依赖时需要联网；安装后的监视器不发出应用网络请求。
签名试用可以用临时签名；长期安装需要一个稳定的本地代码签名身份。
权限需要手动授予「完全磁盘访问权限」。
不需要Homebrew、Python、Node.js、Docker 或独立的数据库服务器

本地端到端验证在 Apple Silicon 上完成。Intel 机型和全新 Mac 上的安装尚未完整验证；构建脚本默认只为当前架构编译。

安装

DailyDisk 目前以源码形式发布，不是经过公证、下载即用的安装包。构建脚本会编译三个可执行文件、打包资源、签名、校验并安装到 ~/Applications。

1. 安装并检查开发者工具

xcode-select --install

安装完成后，打开新的终端窗口检查：

swift --version
xcrun --sdk macosx --show-sdk-version
git --version

2. 获取源码

git clone https://github.com/Nu1sance/DailyDisk.git
cd DailyDisk

之后的命令都在这个目录里运行。也可以直接 下载源码 ZIP 解压使用。首次构建会自动拉取依赖，耗时比之后长。

3a. 一次性试用（临时签名）

ALLOW_ADHOC_SIGNING=1 Scripts/build-app.sh --install
open "$HOME/Applications/DailyDisk.app"

临时签名只适合试用。替换构建后，已授予的「完全磁盘访问权限」或通知权限可能失效，需要重新授权。

3b. 长期安装（使用你自己的签名身份）

先列出钥匙串中有效的代码签名身份。一个身份包括证书和它的私钥；构建脚本不会替你创建。

security find-identity -v -p codesigning

使用 Apple 开发身份：

CODE_SIGN_IDENTITY="Apple Development: Your Name (TEAMID)" \
  Scripts/build-app.sh --install
open "$HOME/Applications/DailyDisk.app"

使用在「钥匙串访问」中自建的本地代码签名身份时，可以关闭 Apple 安全时间戳请求：

CODE_SIGN_IDENTITY="DailyDisk Local Signing" CODE_SIGN_TIMESTAMP=none \
  Scripts/build-app.sh --install

上面的身份名称只是示例，请换成 security find-identity 列出的名称。之后每次更新都保持同一个身份、默认的 Bundle ID 和 ~/Applications/DailyDisk.app 安装路径。私钥只留在你的 Mac 上，不要提交到仓库。

首次设置

  1. 打开已安装的 App。概览 页会根据当前设置状态只显示一个主要操作。
  2. 如果出现 允许读取磁盘，在 系统设置 → 隐私与安全性 → 完全磁盘访问权限 中启用 ~/Applications/DailyDisk.app。授权后退出并重新打开 App。
  3. 点击 启用每日检查。这会启用后台助手并立即开始一次检查。如果 macOS 需要批准，主按钮会变成 允许后台检查，并打开「登录项与扩展」。
  4. 启用后，用 开始首次检查 或 立即检查。首次检查建立基线，是期初余额；文件增长的比较从下一次成功检查开始。
  5. 通知是可选的，在 设置 → 通用 中开启。拒绝通知不影响报告保存。

日常使用

自动运行

内置的用户级 LaunchAgent 每天当地时间 09:00 运行，登录时也会检查是否有到期的检查。错过的运行会合并为一次；成功执行后进程退出，不常驻。App 窗口不需要保持打开。

关机或未登录的 Mac 无法在 09:00 运行这个用户任务；补查取决于下一次登录或唤醒。DailyDisk 本身不负责开机或唤醒。

立即检查

在 概览 点 立即检查，即使今天的定时报告已经存在也会运行，但仍遵循首次、增量、每周和恢复策略。检查过程中显示阶段、真实计数、已用时间和上次进度更新的时间，不会编造百分比。

关闭窗口与取消

  • 检查在后台助手中进行，可以随时关闭窗口；重新打开后会自动接上进度。
  • 在开始保存之前可以点 取消检查，之前的基线会保留。保存阶段会提示「正在保存结果，请稍候。此阶段不可取消。」
  • 如果助手意外停止，App 会给出可操作的中断提示，用 重试检查 重新开始，而不是一直转圈。
  • 需要强制完整清点时，使用 设置 → 通用 → 重新完整检查磁盘。

完整对账的时机

距上次完整清点满 168 小时（七个滚动日）时做一次完整对账。事件日志丢失或被替换、拓扑变化或清单漂移，会提前触发恢复性的完整扫描，所以不是每次例行检查都能走增量。

读懂报告

概览 显示最近一次的磁盘变化和主要增长来源。历史 可以按日期、运行和域选择报告，查看记账、覆盖范围、物理诊断、排名和错误。记账与诊断默认折叠。

磁盘的物理变化由三部分组成，分开记录：

物理变化 = 净文件变化 + 未归属的 APFS 差异 + DailyDisk 自身开销

字段含义
eventAttributedDelta由文件事件归属到路径的变化
reconciliationCorrection完整对账产生的带符号修正
reconciledIndexedDelta对账后的索引净变化
dailyDiskOverheadDeltaDailyDisk 自身数据的变化
physicalUsedDeltaAPFS 报告的物理已用空间变化
physicalUnattributedDelta无法安全归属到路径的物理差异

修正值的正负：正值表示完整扫描发现了增量维护漏掉的已分配字节；负值表示增量索引保留了实际已不存在的字节。未归属的物理空间不会被硬塞进一个虚构的目录。

环形图

概览和报告详情会为最多五个互不重叠的正向条目画出环形图。计算百分比前会排除祖先目录和重复路径；分母只是图中显示的这几项，不是全部文件增长，也不是磁盘的物理变化。负向变化和未归属的 APFS 空间不会成为扇区。

报告以成对的 JSON 和 Markdown 原子写入：

~/Library/Application Support/DailyDisk/Reports/<run-uuid>/

隐私与数据

DailyDisk 只在本地保存数据：

~/Library/Application Support/DailyDisk/DailyDisk.sqlite
~/Library/Application Support/DailyDisk/Reports/
~/Library/Application Support/DailyDisk/Logs/
~/Library/Application Support/DailyDisk/AlertState.json
~/Library/Application Support/DailyDisk/Control/
  • 没有遥测，不用云存储，不需要 root helper、sudo 或 LaunchDaemon。
  • 界面默认隐藏路径；显示路径只在当前会话有效，导出完整 JSON 需要二次确认。
  • 通知只包含总字节数，从不包含完整路径。运行日志对敏感字符串做哈希。
  • 进度与控制文件只包含阶段、ID、时间和计数，不含路径或任意命令。

命令行

日常的扫描、历史、报告、健康检查和重置都能在 App 里完成。dailydiskctl 用于自动化、严格只读的检查、机器可读的退出码和专家排障。已安装的副本位于：

"$HOME/Applications/DailyDisk.app/Contents/Helpers/dailydiskctl" status

常用子命令：

dailydiskctl status
dailydiskctl history --limit 14
dailydiskctl report
dailydiskctl verify
dailydiskctl diagnostics

默认不输出路径。需要路径排名或可还原的 JSON 时，必须显式同意：

dailydiskctl report --include-paths
dailydiskctl report --include-paths --json

更新

拉取新版本后，用相同的签名变量加 --install 重新构建，然后退出并重新打开 App 以载入新版本。避免在扫描进行中替换助手。目前没有自动更新。

git pull
CODE_SIGN_IDENTITY="你的签名身份" Scripts/build-app.sh --install

卸载

  1. 打开 DailyDisk → 设置 → 移除每日任务。
  2. 如果要删除本地历史，使用 设置 → 重置历史与基线。它会注销助手、确认没有写入进程后，只删除 DailyDisk 自己的数据目录。
  3. 退出 DailyDisk，删除 ~/Applications/DailyDisk.app。
  4. 如果系统设置中仍有条目，从「完全磁盘访问权限」和「通知」中移除 DailyDisk。

已知限制

  • 完全磁盘访问权限不能绕过 POSIX 权限、ACL、SIP 或签名系统卷。无法读取的子目录会被报告，并沿用上一次的清单，不会被当作删除。
  • FSEvents 是会合并事件的变化日志，不是审计日志。日志丢失或回绕时会触发权威的完整恢复。
  • 两次检查之间创建又删除的文件无法还原，除非它们仍通过打开的文件描述符或快照占用空间。
  • APFS 克隆、共享区段、快照、元数据和可清除空间，使逐文件的精确物理占用无法计算；DailyDisk 会明确报告剩余差额。
  • 「已删除但仍被打开」的文件大小是逻辑值，不一定等于独占的 APFS 块。
  • 快照的大小字段是可选的，不会被盲目相加。

疑难排查

现象处理
找不到编译器或 SDK安装或更新 Apple 开发者工具，确认 swift --version 为 6 以上、SDK 为 15 以上。
依赖拉取失败确认能访问 GitHub，然后重试 swift package resolve。
没有签名身份先用临时签名试用，或按「长期安装」准备本地签名身份。不要关闭签名检查。
更新后权限丢失确认签名身份、Bundle ID 和安装路径都没有变，再重新授权。
完整扫描很慢首次基线在约 236 万条路径的 Mac 上用了 23–24 分钟，属于正常范围；耗时受文件数量、改动量和磁盘速度影响。
