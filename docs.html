DAILYDISK · 用户文档

安装、设置与日常使用

从构建安装到读懂报告的完整流程。架构、数据库与记账细节见仓库的 Docs 目录。

概述

DailyDisk 是一款以图形界面为主、从源码构建的 macOS 磁盘增长监视器。它每天清晨完整清点一次内置 APFS 磁盘，与上一次的清单比较，把文件变化归到具体路径。无法安全归属的 APFS 物理差异单独记录。

监视范围：

  • 内置 APFS 容器，以及 System、Data、VM、Preboot、Recovery、Update 各角色的卷
  • /System/Volumes/Data，启动盘上唯一的完整清点范围
  • FSEvents 持久日志中的文件变化
  • 新增、删除、移动、硬链接和尺寸变化的文件
  • 每天一次的完整清点，默认 05:00
  • APFS 快照成员关系与容器容量
  • 已删除、仍被进程打开的文件
  • DailyDisk 自身的数据库、报告与日志占用

密封的系统卷等不做清点的角色只显示卷级指标。外置、可移除、网络与磁盘映像默认不纳入。

系统要求

项目要求
系统macOS 15 或更高，内置 APFS 启动盘
构建工具Apple 命令行工具或完整 Xcode，提供 Swift 6+ 与 macOS 15+ SDK。新 Mac 通常未预装。
网络首次克隆与解析 SwiftPM 依赖时需要。安装后的监视器不发出网络请求。
签名试用可用临时签名；长期安装需要稳定的本地代码签名身份。
权限需手动授予「完全磁盘访问权限」。
不需要Homebrew、Python、Node.js、Docker 或独立数据库服务

端到端验证在 Apple Silicon 上完成。Intel 机型与全新 Mac 的安装尚未完整验证；构建脚本只为当前架构编译。

安装

DailyDisk 以源码形式发布，没有公证的安装包。构建脚本会编译三个可执行文件、打包、签名、校验，并安装到 ~/Applications。

1. 安装并检查开发者工具

xcode-select --install

安装完成后，在新的终端窗口中检查：

swift --version
xcrun --sdk macosx --show-sdk-version
git --version

2. 获取源码

git clone https://github.com/Nu1sance/DailyDisk.git
cd DailyDisk

后续命令都在此目录运行。也可以 下载源码 ZIP。首次构建会自动拉取依赖，耗时较长。

3a. 一次性试用（临时签名）

ALLOW_ADHOC_SIGNING=1 Scripts/build-app.sh --install
open "$HOME/Applications/DailyDisk.app"

临时签名仅供试用。重新构建后，已授予的完全磁盘访问权限或通知权限可能失效。

3b. 长期安装（使用自己的签名身份）

先列出钥匙串中有效的代码签名身份。身份由证书和私钥组成，构建脚本不会代为创建。

security find-identity -v -p codesigning

使用 Apple 开发身份：

CODE_SIGN_IDENTITY="Apple Development: Your Name (TEAMID)" \
  Scripts/build-app.sh --install
open "$HOME/Applications/DailyDisk.app"

使用在「钥匙串访问」中自建的本地身份时，可关闭 Apple 安全时间戳：

CODE_SIGN_IDENTITY="DailyDisk Local Signing" CODE_SIGN_TIMESTAMP=none \
  Scripts/build-app.sh --install

以上身份名称仅为示例，请换成 security find-identity 列出的名称。之后每次更新保持同一身份、默认 Bundle ID 与 ~/Applications/DailyDisk.app 安装路径。私钥只留在本机。

首次设置

  1. 打开 App。概览 只显示一个与当前状态相符的主要操作。
  2. 如出现 允许读取磁盘，在 系统设置 → 隐私与安全性 → 完全磁盘访问权限 中启用 ~/Applications/DailyDisk.app，然后退出并重新打开 App。
  3. 点击 启用每日检查，后台助手随即启用并开始一次检查。如需系统批准，主按钮会变为 允许后台检查，并打开「登录项与扩展」。
  4. 使用 开始首次检查 或 立即检查。首次检查建立基线，作为期初余额；增长比较从下一次成功检查开始。
  5. 通知可选，在 设置 → 通用 中开启。拒绝通知不影响报告保存。

日常使用

每日完整检查

后台助手每天当地时间 05:00 完整读取一次文件元数据。登录时也会检查是否有待办；当天已有成功的完整检查，就跳过。运行结束即退出，App 窗口无需保持打开。

完整检查只依赖当次扫描。清点期间的改动由 FSEvents 补齐，不需要前一天的日志仍然有效。是否完成以清单实际提交、报告发布的时间为准，延迟发布的昨日结果不算作今天。

关机或未登录时任务无法运行，补查取决于下一次登录或唤醒。DailyDisk 不负责开机或唤醒。

立即检查

在 概览 点击 立即检查：

  • 当天还没有完整检查时，执行完整检查。
  • 当天已完成完整检查后，再次检查会尝试增量；事件日志不可信时自动改为完整检查。
  • 已有检查在进行时，直接接入那一次。
  • 需要强制完整清点，使用 设置 → 通用 → 重新完整检查磁盘。

检查过程显示阶段、真实计数、已用时间与上次进度更新时间，不显示估算的百分比。遍历结束后会进入 正在核对已删除的文件 阶段；如有读不到的目录，还会显示 正在保留无法读取目录的历史记录。

关闭窗口与取消

  • 检查在后台助手中进行，窗口可随时关闭，重新打开后自动接上进度。
  • 开始保存前可 取消检查，之前的基线保留。保存阶段会提示「正在保存结果，请稍候。此阶段不可取消。」
  • 失败或取消的检查不计为当天完成。
  • 助手意外停止时，App 会给出中断提示，用 重试检查 重新开始。

存储方式

建立基线后，每日完整检查与当前清单逐批比对，只写入发生变化的记录，未变化的文件不重写。变更前的旧值保留 24 小时，用于恢复，过期后在后续运行中清理。

读懂报告

概览 显示最近一次的磁盘变化、增长来源与趋势。历史 可按日期、运行和域选择报告，查看记账、覆盖范围、物理诊断、排名与错误；记账与诊断默认折叠。

空间构成

物理变化 = 净文件变化 + 未归属的 APFS 差异 + DailyDisk 自身开销

「空间构成」卡片按上式展示三项。各项同号时显示比例条；未归属空间的说明在卡片的信息按钮里。

增长与释放

概览和报告详情各列出最多五项互不重叠的增长和释放来源。先排除祖先目录与重复路径；每行的条形只相对于列表中最大的一项，不代表全部文件增长或磁盘物理变化。未归属的 APFS 空间不会出现在来源列表中。完整排名，包括重叠的祖先目录、分配字节与逻辑字节，在报告的折叠详情里。

趋势与路径

  • 指针移到概览趋势的某一列，可查看该次报告的时间与带符号的物理变化。增加为蓝色，减少为灰色，选中时变为柔和的黄色。
  • 历史工具栏显示当前路径状态：「路径已隐藏」或「路径已显示」。显示路径需确认，仅在当前会话有效；隐藏立即生效。

记账字段

字段含义
eventAttributedDelta由文件事件归属到路径的变化
reconciliationCorrection完整检查产生的带符号修正
reconciledIndexedDelta修正后的索引净变化
dailyDiskOverheadDeltaDailyDisk 自身数据的变化
physicalUsedDeltaAPFS 报告的物理已用空间变化
physicalUnattributedDelta无法安全归属到路径的物理差异

修正值为正，表示完整扫描发现了增量维护漏记的字节；为负，表示索引保留了实际已不存在的字节。

报告以 JSON 与 Markdown 成对原子写入：

~/Library/Application Support/DailyDisk/Reports/<run-uuid>/

回收自身占用

数百万文件的清单本身可能占用数 GB。打开 设置 → 诊断 → 数据占用：

  • 刷新占用 显示当前占用、数据库内可复用的空间和上次维护结果。
  • 回收数据库空间 交由后台助手整理数据库。当前基线与历史报告保留，不扫描文件。

回收需要每日任务已安装并获批准，还需要临时空间：约为数据库大小的两倍再加 1 GB，不足时会明确拒绝。维护开始后不可取消，可以关闭窗口等待完成。不要手动删除 SQLite 或 WAL 文件。

自动压缩受 1 GB、25% 与七天冷却期限制，不会每天执行。每日检查会复用数据库中的空闲页，频繁压缩反而会让这些空间被重新分配。

隐私与数据

数据只保存在本机：

~/Library/Application Support/DailyDisk/DailyDisk.sqlite
~/Library/Application Support/DailyDisk/Reports/
~/Library/Application Support/DailyDisk/Logs/
~/Library/Application Support/DailyDisk/AlertState.json
~/Library/Application Support/DailyDisk/Control/
  • 没有遥测，不用云存储，不需要 root、sudo 或 LaunchDaemon。
  • 界面默认隐藏路径；显示路径仅限当前会话，导出完整 JSON 需再次确认。
  • 通知只包含总字节数。运行日志中的敏感字符串经过哈希。
  • 进度与控制文件只记录阶段、ID、时间和计数，不含路径或命令。

命令行

日常操作都能在 App 中完成。dailydiskctl 用于自动化、严格只读的检查、机器可读的退出码与排障。已安装的副本位于：

"$HOME/Applications/DailyDisk.app/Contents/Helpers/dailydiskctl" status

常用子命令：

dailydiskctl status
dailydiskctl history --limit 14
dailydiskctl report
dailydiskctl verify
dailydiskctl diagnostics

默认不输出路径。需要路径排名或可还原的 JSON 时须显式同意：

dailydiskctl report --include-paths
dailydiskctl report --include-paths --json

更新

拉取新版本后，用相同的签名变量加 --install 重新构建，再退出并重新打开 App。App、后台助手与命令行工具需一起更新；不要在检查进行中替换助手。目前没有自动更新。

git pull
CODE_SIGN_IDENTITY="你的签名身份" Scripts/build-app.sh --install

从旧版升级：新版的每日检查在 05:00。旧安装注册的可能仍是 09:00，更新后请确认计划时间。数据库会自动迁移，原有清单与历史报告保留，无需重置。

卸载

  1. 打开 DailyDisk → 设置 → 移除每日任务。
  2. 如需删除本地历史，使用 设置 → 重置历史与基线。它会注销助手，确认没有写入后，只删除 DailyDisk 自己的数据目录。
  3. 退出 DailyDisk，删除 ~/Applications/DailyDisk.app。
  4. 如系统设置中仍有条目，从「完全磁盘访问权限」与「通知」中移除。

已知限制

  • 完全磁盘访问权限不能绕过 POSIX 权限、ACL、SIP 与签名系统卷。读不到的子目录会被报告，并沿用上一次的清单，不计为删除。
  • FSEvents 会合并事件，不是审计日志。日志丢失或回绕时会触发完整恢复。
  • 两次检查之间创建又删除的文件无法还原，除非仍通过打开的文件描述符或快照占用空间。
  • APFS 克隆、共享区段、快照、元数据与可清除空间，使逐文件的精确物理占用无法计算；剩余差额会明确报告。
  • 「已删除仍被打开」的文件大小是逻辑值，不一定等于独占的 APFS 块。
  • 快照大小字段是可选的，不会被直接相加。

疑难排查

现象处理
找不到编译器或 SDK安装或更新 Apple 开发者工具，确认 Swift 为 6 以上、SDK 为 15 以上。
依赖拉取失败确认能访问 GitHub，然后重试 swift package resolve。
没有签名身份先用临时签名试用，或按「长期安装」准备本地签名身份。不要关闭签名检查。
更新后权限丢失确认签名身份、Bundle ID 与安装路径未变，再重新授权。
升级后仍在 09:00 运行App、助手与计划任务需一起更新。重新构建安装后确认注册的时间为 05:00。
完整检查耗时在一台约 232 万条路径的 Mac 上，每日完整检查约 8 分 41 秒；首次建立基线需要更久。耗时受文件数量、改动量与磁盘速度影响。
数据库占用过大使用 回收数据库空间，确保有足够的临时空间。
